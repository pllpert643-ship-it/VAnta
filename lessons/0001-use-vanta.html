บทเรียน 1: ใช้ VAnta จัดคิวงาน GPU

เป้าหมาย: เปิดแอป รันเดโม อ่านเหตุผลของคิว และเลือกเครื่องมือให้เหมาะกับงาน

ภาพจำ: VAnta ไม่ได้เร่ง GPU ให้แรงขึ้น แต่เป็นผู้จัดคิวที่ป้องกันงานชนกันและอธิบายการตัดสินใจ

1. เริ่มจาก Demo Scenario

กด Run demo scenario
VAnta จะใส่งานตัวอย่าง 3 งาน: Balanced (Normal), Critical และ VRAM guard check

เปิดตาราง Workload queue แล้วดูการเปลี่ยนสถานะ งานที่กำลังทำจะเป็น RUNNING งานที่รอทรัพยากรจะเป็น WAITING และงานที่ไม่ผ่านกฎจะเป็น FAILED พร้อมเหตุผลในคอลัมน์ DECISION

2. อ่าน Decision Feed

อ่านจากเหตุการณ์ล่าสุดด้านบน:

ข้อความคุณควรเข้าใจว่า
entered the ... queueงานถูกส่งเข้าคิวแล้ว
Started ...กฎผ่านและ VAnta เปิด process
Waiting for ... VRAMต้องรอพื้นที่ VRAM ให้พอ
Concurrency limit reachedมีงานควบคุมอยู่แล้ว จึงยังไม่เริ่มงานใหม่
Rejected ... safe capacityงานใหญ่เกินพื้นที่หลังหัก reserve 512 MB
Verified ... VRAM changedVAnta ตรวจผลหลังเริ่มงาน

3. เลือกปุ่มให้ตรงงาน

Add GPU Pulse to queue
ใช้เมื่ออยากทดลองระบบด้วย workload ที่เตรียมไว้ เลือกขนาดและ Priority
Submit custom command
ใช้เมื่อมีโปรแกรม CLI ของตนเอง ระบุ VRAM ที่คาดว่าจะใช้ให้ใกล้เคียงจริง
Open Policy Lab
ใช้เรียนรู้ความต่างของนโยบายคิวโดยไม่เปิด process จริง

4. ประโยชน์ในสถานการณ์จริง

  • VRAM จำกัด: กัน reserve ไว้เพื่อลดโอกาส allocation ล้มเหลว
  • หลายงาน: priority ทำให้งานสำคัญได้สิทธิ์ก่อนตามกฎที่มองเห็นได้
  • ตรวจสอบย้อนหลัง: SQLite เก็บ job และ decision history ไว้ดูสาเหตุ
  • หลังแอปหยุดผิดปกติ: VAnta ตรวจ child process เดิมก่อนเปิดคิวต่อ
ข้อจำกัดสำคัญ: VAnta ควบคุมเฉพาะ process ที่เปิดผ่าน VAnta และ CUDA Pulse ต้องใช้ NVIDIA GPU กับไดรเวอร์ที่ทำงานได้
